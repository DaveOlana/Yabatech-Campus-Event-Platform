# UNIVERSAL ABOUT US PAGE — BUILDER GUIDELINES

## Objective

Create a concise, informative, attractive, and responsive About Us page that reflects the identity and purpose of the current project.

**This file is a guide, not a fixed design template.** Every implementation must be adapted to its own project.

## 1. Understand the Project First

Before implementation, study the existing repository to understand:

- The project's purpose, target audience, and principal features.
- Its actual user journeys and functionality.
- Its existing theme, visual identity, and design conventions.
- Any documentation explaining how the project should be used.

Use this information to determine the appropriate About Us content. Never invent functionality or describe proposed features as implemented.

## 2. About Us Page Structure

Keep the page relatively short, clear, and engaging.

It should generally communicate:

1. **Project Overview:** What the project is, why it exists, and whom it serves.
2. **Key Capabilities:** A brief explanation of its most important features.
3. **How to Use It:** A practical guide only if the project would benefit from one.
4. **Additional Information:** Important limitations, notices, or other relevant details when necessary.

These are content guidelines, not compulsory headings.

The builder may reorganize, combine, or omit sections based on the project's needs.

Avoid unnecessary paragraphs, repetitive descriptions, excessive technical explanations, or lengthy promotional content.

## 3. Visual Design

The page must naturally belong to the existing project.

- Follow its established colours, typography, spacing, and visual language.
- Use clean, readable layouts with deliberate whitespace.
- Keep visual elements purposeful rather than decorative.
- Include subtle animations or illustrations only where they improve the experience.
- Ensure excellent mobile and desktop responsiveness.
- Avoid overloading the page with cards, large headings, or excessive graphics.

Do not impose a predetermined visual theme or reuse the branding of another project.

## 4. Usage Guide

Include a guide only when it makes the project easier to understand or use.

Explain the most important actions in a few simple steps.

Use real interface terminology and, where useful, relevant screenshots or visual explanations.

Avoid turning the About Us page into a complete user manual.

## 5. Personal Logo Integration

The repository contains an `about us process` folder with:

- `developer-logo.png` — the supplied personal logo.
- `portfolio.txt` — the portfolio URL.
- `ABOUT_US_INSTRUCTIONS.md` — this guideline.

Integrate the supplied logo subtly into the About Us page, preferably near the bottom.

**Branding rules:**

- Keep the logo relatively small and visually unobtrusive.
- Preserve its original proportions and appearance.
- Do not modify or recreate the logo unnecessarily.
- The logo may link directly to the portfolio URL supplied in `portfolio.txt`.
- Do not create a large personal attribution section.
- Do not automatically display a developer's name, biography, personal tagline, or professional achievements.
- Do not add statements such as "Built by," "Developed by," or "Created by" unless the project owner explicitly requests them.
- Never imply that the logo owner is the sole creator, owner, or official representative of the project.

The logo should function as a **discreet visual signature**, acknowledging involvement without competing with the identity or ownership of the project.

## 6. Implementation Rules

Reuse existing project components and conventions where practical.

Implement or improve the About Us page without unnecessarily changing unrelated application functionality.

Keep the page maintainable, accessible, and consistent with the rest of the website.

Do not introduce database migrations, authentication changes, or additional dependencies unless genuinely required and approved.

## 7. Quality Assurance

Before completion, verify that:

- The description accurately represents the project.
- The page is concise and appropriately structured.
- All described functionality exists.
- The visual design matches the current application.
- The page works properly on mobile and desktop.
- The logo is correctly displayed and unobtrusive.
- The portfolio link is correct, where used.
- No unwanted personal attribution or ownership implication appears.
- Existing project functionality remains unaffected.

## Final Directive

**The project must remain the focus of its About Us page.**

Explain its purpose, communicate its usefulness, guide visitors where necessary, and preserve its established identity.

Integrate the supplied personal logo as a subtle signature of involvement, without drawing attention away from the project or its owners.

**Keep it short, accurate, attractive, and project-specific.**
